# 工作站硬件门禁（2026-09-23）

目标主机：`192.168.1.140`，Ubuntu 24.04，4×Tesla V100-SXM2-16GB；物理 GPU 0 是 Quadro K620，已排除。

## P2P/NVLink

- 物理 GPU 1–4：每卡 16384 MiB，compute capability 7.0。
- `nvidia-smi topo -m`：V100 之间均为 `NV2`。
- `nvidia-smi topo -p2p r`：V100 之间全为 `OK`；K620 与 V100 为 `NS`。
- PyTorch 2.10.0+cu128，NCCL 2.27.5+cuda12.9，进程可用架构包含 `sm_70`。

## NCCL smoke

命令：

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1,2,3,4 \
  torchrun --standalone --nproc_per_node=4 scripts/nccl_smoke.py \
  --megabytes 32 --iters 10
```

实测输出：

```text
world=4, bytes_per_tensor=33554432,
avg_seconds=0.0005346578, aggregate_gib_s=87.6729, max_error=0.0
```

这只证明四卡通信门禁通过，不代表 MiniMax H3 已加载或达到任何生成速度。之后的 TP4 测试必须继续保留 `CUDA_DEVICE_ORDER=PCI_BUS_ID`，否则 PyTorch 可能把物理 K620 映射进进程，导致 `no kernel image is available for execution on the device`。
