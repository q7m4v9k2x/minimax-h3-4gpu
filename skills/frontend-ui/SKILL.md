# Frontend UI

> **按需读取：**
> - `SKILL.md` — 入口、边界和快速流程
> - `DESIGN-SYSTEM.md` — 视觉令牌、组件状态与交互规则
> - `WORKFLOW.md` — 从审查到实现、验证和交付的工作流

## 何时使用

- 新建或重构 HTML/CSS/JS 页面、WebUI、控制台、生成器界面。
- 需要统一视觉、改善信息层级、加入加载/队列/进度/错误/空状态。
- 需要移动端适配、键盘操作、屏幕阅读器支持或截图回归。

## 默认边界

- 默认采用无构建依赖的原生 HTML、CSS、JavaScript；沿用项目已有运行方式，不擅自引入框架、打包器或 CDN。
- 先读现有页面、API 契约和静态资源，再修改 UI；保持后端字段和 URL 兼容，除非任务明确要求改接口。
- 不把凭据、内网地址或用户数据写进源码；不为展示而伪造实时进度。

## 快速流程

| 步骤 | 动作 | 交付物 |
|---|---|---|
| 1 | 盘点页面、断点、接口和状态 | 页面地图与风险清单 |
| 2 | 按 `DESIGN-SYSTEM.md` 定义令牌和组件状态 | 可复用 CSS/HTML 规则 |
| 3 | 按 `WORKFLOW.md` 实现状态机、进度和响应式布局 | 可运行页面 |
| 4 | 做键盘/屏幕阅读器、窄屏和失败重试检查 | 验收记录 |
| 5 | 固定视口截图并比较关键区域 | 视觉回归结果 |

## 完成标准

页面在加载、空闲、进行中、成功、失败和重试状态都有清楚反馈；进度来自真实事件或明确标注为不确定；窄屏不横向溢出；焦点可见且颜色对比足够；静态资源和脚本在项目现有命令下可直接运行。
